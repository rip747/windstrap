Breakpoints

Use Bootstrap’s breakpoints and media queries to build responsive layouts.

On this page
  • Concepts
  • Available breakpoints
  • CSS variables
  • Media queries

Concepts #

Breakpoints are customizable widths that determine how your responsive layout behaves across device or viewport sizes. Bootstrap’s grid tiers are matched exactly by WindStrap’s Tailwind screens, so the responsive variants (sm:, md:, lg:, xl:, xxl:) fire at the same widths.

Available breakpoints #

Bootstrap includes six default breakpoints, sometimes referred to as grid tiers.

Breakpoint Class infix Dimensions
Extra small None <576px
Small sm ≥576px
Medium md ≥768px
Large lg ≥992px
Extra large xl ≥1200px
Extra extra large xxl ≥1400px

Each breakpoint was chosen to comfortably hold containers whose widths are multiples of 12. Breakpoints are also representative of a subset of common device sizes and viewport dimensions — they don’t specifically target every use case.

CSS variables #

Breakpoints are also exposed as CSS variables in :root: 

:root {
  --bs-breakpoint-xs: 0;
  --bs-breakpoint-sm: 576px;
  --bs-breakpoint-md: 768px;
  --bs-breakpoint-lg: 992px;
  --bs-breakpoint-xl: 1200px;
  --bs-breakpoint-xxl: 1400px;
}

Media queries #

Since WindStrap uses Tailwind’s engine, you write responsive behavior with breakpoint variants in @apply (or directly in your HTML). These are the equivalent of Bootstrap’s min-width media queries: 

/* Bootstrap: @include media-breakpoint-up(md) { … } */
.card-body { @apply md:flex md:justify-between; }

/* Bootstrap: .d-md-none */
.element { @apply md:hidden; }

These translate into real @media (min-width: …) queries in the compiled output, exactly like Bootstrap’s.
