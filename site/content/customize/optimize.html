Why you should tree-shake #

Bootstrap ships a full stylesheet — you almost never use all of it. The same is true for WindStrap’s dist/windstrap.css, which includes every translated class.

Because every WindStrap class is defined with Tailwind’s @apply, you can take advantage of Tailwind’s JIT engine to emit only the rules you actually use.

How it works #

Tailwind scans your templates for class names. When you add your HTML/JS to the content array of tailwind.config.js, Tailwind keeps only the generated utilities that are referenced — including those applied inside WindStrap’s @apply rules. 


// tailwind.config.js
module.exports = {
  content: [
    './index.html',
    './src/**/*.{html,js}',
    // add your own templates, e.g.:
    './templates/**/*.html',
    './public/js/**/*.js',
  ],
  // …
}
Keep CSS files out of content

Do not add src/**/*.css to content — Tailwind would see the WindStrap class names in the CSS and regenerate colliding default utilities that override the translated values. Only scan HTML/JS.

Building for production #


# Generate + compile (JIT output only includes used utilities)
npm run build

The output dist/windstrap.css is the full translation. To produce a trimmed build, add your templates to content and rebuild — Tailwind will drop the @apply-inlined rules that nothing references.

Compared to Bootstrap #

Bootstrap removes unused components by commenting out @imports in Sass. WindStrap instead relies on Tailwind’s JIT, so you don’t have to curate a list of includes — you simply stop using a class and it stops appearing in the build.
