About WindStrap customization #

Bootstrap is customized through a layer of Sass variables, maps, mixins and functions. WindStrap keeps the output of that system: the CSS custom properties (design tokens) that Bootstrap emits into :root and every component, translated into Tailwind utilities via @apply.

The practical result is that you customize WindStrap the same way you customize Bootstrap at runtime — by overriding the --bs-* CSS variables — without recompiling any Sass. For compile-time changes, you edit the source:

  • Colors & fonts → tailwind.config.js (theme.extend.colors, theme.extend.fontFamily)
  • Breakpoints → tailwind.config.js (theme.screens)
  • Component rules → src/sections/*.css (the @apply translations)
  • Design tokens → src/sections/root.css (:root custom properties)

A quick example #

Want a different primary color? Override the token at runtime, or in your own stylesheet:

Badge Colored link 

:root {
  --bs-primary: #6f42c1;
  --bs-primary-rgb: 111, 66, 193;
  --bs-link-color: #6f42c1;
  --bs-link-hover-color: #5430a0;
}

Because the translated classes use these tokens (e.g. .btn-primary applies bg-primary whose color resolves to var(--bs-primary)), overriding the variable restyles every dependent component at once.
